## 2024-07-02 - HTTP Security Headers Defense-in-Depth
**Vulnerability:** The HTTP control-plane API responses did not include important defense-in-depth security headers like `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, and `Strict-Transport-Security`, leaving the frontend susceptible to injection or clickjacking attacks if served securely.
**Learning:** The React frontend uses a Vite-based module bundler with dynamic ESM lazy loading and WebSocket hot-reloading over `ws:`/`wss:`, and serves a Python fallback HTML shell. Implementing a strict `Content-Security-Policy` directly broke hot-reloading. The policy required specific allowances: `unsafe-inline` for styles and scripts, and explicit addition of `ws: wss:` to `connect-src` in order to support the dynamic shells properly.
**Prevention:** Ensure any HTTP handlers defined manually via `http.server.BaseHTTPRequestHandler` systematically inject defense-in-depth security headers, and tailor `Content-Security-Policy` requirements considering dynamically generated UI shells and WebSocket connections for hot reloading.

## 2024-05-24 - Missing Defense-in-Depth HTTP Security Headers in Raw Server
**Vulnerability:** The control-plane utilizes `http.server.BaseHTTPRequestHandler` directly for its HTTP serving shell instead of a framework like FastAPI that might have built-in secure header defaults or standard middleware. Because of this, it was completely missing Defense-in-Depth security headers (`X-Content-Type-Options`, `X-Frame-Options`, `X-XSS-Protection`, `Strict-Transport-Security`, `Content-Security-Policy`).
**Learning:** When using raw, low-level HTTP servers in Python (or any language) to serve APIs or fallback UI shells, security headers are never present by default and must be explicitly crafted and injected before calling `.end_headers()`. Furthermore, strict CSP policies must account for frontend architectures like Vite which rely heavily on 'unsafe-inline' for styles and initialization scripts.
**Prevention:** In future greenfield projects or raw HTTP implementations, always establish a central `_send_security_headers()` middleware or helper function early in the development lifecycle to ensure all responders return secure defaults.

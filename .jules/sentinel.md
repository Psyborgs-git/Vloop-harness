## 2024-05-15 - Missing Defense-in-Depth Security Headers on BaseHTTPRequestHandler
**Vulnerability:** The control plane HTTP shell (`control-plane/cp/http_responders.py`) used `http.server.BaseHTTPRequestHandler` but did not manually inject standard defense-in-depth security headers (`X-Content-Type-Options`, `X-Frame-Options`, `X-XSS-Protection`, `Strict-Transport-Security`, `Content-Security-Policy`), leaving the application exposed to clickjacking, MIME-type sniffing, XSS, and other web vulnerabilities.
**Learning:** Frameworks like FastAPI or Express often provide middleware for security headers out-of-the-box, but when using raw handlers like `BaseHTTPRequestHandler` (often chosen for minimal dependencies or specific architectural constraints), these headers must be manually injected into every response type (JSON, HTML, File). Additionally, the CSP must be carefully crafted to permit essential application features (e.g., `'unsafe-inline'` for React hot-reloading and `ws:` for WebSockets) without becoming overly permissive.
**Prevention:** Establish a standardized `_send_security_headers()` helper function and enforce its use across all response generation paths within raw HTTP handlers. Ensure architectural reviews check for manual header injection when standard frameworks are bypassed.
